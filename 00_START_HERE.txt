================================================================================
CACHE-BUST MECHANISM (TECHNICAL)
================================================================================

Problem:
  - Browser caches old app.js
  - New deployment happens
  - Users still see old code

Solution:
  - Stable app.js filename (no content hash)
  - Versioned query parameter ?v=<SHA>
  - When code changes, SHA changes
  - Browser sees new query param, re-fetches

Script Tag:
  <script src="./app.js?v=f785306"></script>

How It Works:
  1. Vite outputs index.js (stable, no hash)
  2. postbuild.mjs renames index.js → app.js
  3. postbuild.mjs injects versioned script tag
  4. When code changes, new SHA generated
  5. Query param updates to new SHA
  6. Browser can't use cached file with old SHA
  7. Forces re-fetch of new version
  8. Users get latest code

================================================================================
BOOT PROOF MECHANISM (TECHNICAL)
================================================================================

Purpose:
  - Prove the new code is actually running
  - Not just that files exist, but that they execute

Mechanism:
  - captureBootProof() IIFE in main.ts
  - Executes on module load (first time)
  - Logs to browser console: [UI_BOOT_PROOF]

Output Example:
  [UI_BOOT_PROOF] ui_build=f785306 time=2026-01-18T14:01:33Z scripts=[./app.js?v=f785306]

Shows:
  - Exact SHA of code running (f785306)
  - When it loaded (timestamp)
  - Which scripts were loaded (app.js?v=f785306)
  - Proves it's new code (not cached version)

Footer Display:
  - Shows SHA, time, exact loaded script URL
  - Updates when code version changes
  - Visual confirmation for testing
