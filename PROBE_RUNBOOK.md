# FORENSIC_PROBE: Production Correlation Proof Runbook

## Overview

The **Forensic Probe** is an undeniable end-to-end proof mechanism that demonstrates:

1. **UI → Backend Invocation Works** - The UI can successfully call a resolver
2. **Correlation Proof** - A unique nonce generated by the backend can be found in production logs
3. **Full Stack Integration** - From button click to backend execution to log capture

This runbook provides step-by-step instructions to generate and verify proof that the gadget UI successfully invokes the backend probe resolver.

---

## Quick Start (3 Steps)

### Step 1: Click "Run Probe" in the Dashboard

1. Open the Jira dashboard with the Firsttry gadget installed
2. Scroll down to the **"🔬 Forensic Probe (Production Correlation Proof)"** section
3. Click the **"Run Probe"** button
4. Wait for the response (typically 1-2 seconds)

### Step 2: Copy the Nonce Grep Command

When the probe completes, you'll see:

```
✅ Probe completed at 14:35:22

Grep Commands (Copy-Paste for Manual Verification)

Nonce Grep (Definitive):
bash tools/probe_prod.sh --nonce probe_1768662844441_af14b920
```

**Copy this command exactly** (including the nonce value).

### Step 3: Run the Verification Script

Open a terminal and paste the command:

```bash
cd /path/to/workspace
bash tools/probe_prod.sh --nonce probe_1768662844441_af14b920
```

Expected output:

```

================================

PROBE_NONCE: probe_1768662844441_af14b920
Output dir:  /tmp/ft_probe_20250117_143522

... (log capture and verification) ...
```

If you have both the UI_REQ_ID and PROBE_NONCE, you can use the legacy format:

```bash
bash tools/probe_prod.sh <UI_REQ_ID> <PROBE_NONCE>
```

Example:

```bash
bash tools/probe_prod.sh ui_1768662844441_af14b920 probe_1768662844441_af14b920
```


## Troubleshooting

### No Response from "Run Probe"

**Symptom:** Button shows "Running probe..." but never completes

**Possible Causes:**
1. Backend resolver not deployed
2. Resolver allowlist missing 'probe'
3. Network/CORS issue

**Fix:**
```bash
# Verify probe resolver is in allowlist
grep -A 20 "ALLOWED_RESOLVERS" src/resolvers/gadget-handlers.ts

# Check backend logs for errors
cd atlassian/forge-app
forge logs --environment production --limit 100 | tail
```

### Nonce Not Found in Logs

**Symptom:** Verification script says "PROBE nonce NOT found"

**Possible Causes:**
1. Logs were rolled/rotated
2. Backend wasn't actually executed
3. Nonce is wrong/typo

**Fix:**
```bash
# Re-run probe to get a fresh nonce
# Then immediately verify (before log rotation)
bash tools/probe_prod.sh --nonce <new_nonce>

# Check if any probe markers were logged
forge logs --environment production --limit 5000 | grep "marker.*PROBE"
```

### Build SHA Mismatch

**Symptom:** UI footer shows different SHA than probe response

**Possible Causes:**
1. UI is stale (old browser cache)
2. Different deployment versions

**Fix:**
```bash
# Hard refresh the browser
Ctrl+Shift+R (or Cmd+Shift+R on Mac)

# Remove and re-add the gadget
# Check that both UI and backend are from same deploy date
```

## Deployment Checklist

Before deploying to production, ensure:

- [ ] `probe` resolver is in `ALLOWED_RESOLVERS` in `src/resolvers/gadget-handlers.ts`
- [ ] `gadget-handlers.ts` exports the `probe` function
- [ ] UI has the `runProbe` function and button (should see "🔬 Forensic Probe" section)
- [ ] `tools/probe_prod.sh` exists and is executable
- [ ] Gadget builds without errors: `npm run build` in `src/gadget-ui/`
- [ ] Forge app deploys without errors: `forge deploy --environment production`

## FAQ

**Q: Does running probe affect production data?**
A: No. The probe resolver is read-only and generates no side effects. It only logs a JSON marker and returns a response.

**Q: Can users see the probe nonce in logs?**
A: The nonce is a random hex string that's meaningless without context. It's safe to share publicly as it's not a secret.

**Q: How often can I run the probe?**
A: Unlimited. Each run generates a new nonce. Run as frequently as needed for testing/verification.

**Q: Is the probe resolver rate-limited?**
A: No. It's a diagnostic tool designed for manual testing and should not be rate-limited.

**Q: What if I lose the nonce value?**
A: Run the probe again to get a new one. Old nonces will still be in logs, but you'll need to search manually.
