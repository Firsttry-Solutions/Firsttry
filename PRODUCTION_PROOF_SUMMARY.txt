================================================================================
TECHNICAL MECHANISM: CACHE-BUST
================================================================================

PROBLEM:
  - Browser caches old app.js with content hash
  - New version deployed, but users get stale code
  - Only clears on hard refresh or cache clear

SOLUTION:
  - Stable app.js filename (no content hash)
  - Versioned query parameter ?v=<SHA>
  - When code changes, query param changes
  - Browser can't use cached file with old param
  - Forces fetch on new deploy or gadget re-add

HOW IT WORKS:
  1. Vite outputs index.js (stable filename, no hash)
  2. postbuild.mjs renames index.js → app.js
  3. postbuild.mjs injects: <script src="./app.js?v=f785306"></script>
  4. When code changes, new build generates new SHA
  5. Query param updates to match new SHA
  6. Browser sees different query param
  7. Cache miss - browser fetches new version
  8. Users get latest code after redeploy

PURPOSE:
  - Prove the new code is actually running

MECHANISM:

RESULT:
