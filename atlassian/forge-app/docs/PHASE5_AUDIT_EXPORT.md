# Phase 5: Audit Evidence Export

## Overview

Phase 5 implements a one-click "Trust Snapshot" export system that generates immutable audit evidence in both machine-readable (JSON) and human-readable (PDF) formats.

The export is designed for enterprise security teams to treat as evidence when responding to security questionnaires or audits.

## What the Export Includes

Each Trust Snapshot captures:

1. **Operational State**
   - Current system status (RUNNING / DEGRADED / NOT_RUNNING)
   - Last successful execution timestamp
   - Consecutive days operational

2. **Monitoring Continuity**
   - Scheduler active status
   - Last run timestamp
   - Data completeness (COMPLETE / PARTIAL / EMPTY)

3. **Configuration Risk Summary**
   - Risk band (LOW / MEDIUM / HIGH)
   - Metrics included in assessment
   - Evaluation timestamp

4. **Change Summary (Last 30 Days)**
   - Count of detected configuration changes
   - Categories of changes
   - Most recent change timestamp

5. **App Behavior Guarantees**
   - Read-only operation (true)
   - No Jira API writes (true)
   - No configuration changes (true)
   - No enforcement or automation (true)

6. **Versioning**
   - App version at time of export
   - Deployment environment (production / staging / development)
   - Deployed timestamp (if available)

7. **Evidence Integrity**
   - Snapshot ID (deterministic, based on content)
   - JSON SHA256 hash (immutable fingerprint)
   - Generation timestamp (UTC)

## What the Export Does NOT Claim

This export is factual and observational only. It explicitly does **NOT**:

- Make claims about compliance or regulatory requirements
- Make security assurances beyond the observable operational facts
- Assert alignment with "best practices" or frameworks
- Recommend actions or changes
- Enforce policies or configurations

The export records only what was observed during snapshot generation.

## How to Use the Export

### Generating a Snapshot

1. Open the FirstTry - Audit Evidence Snapshot for Jira dashboard gadget
2. Scroll to the "Audit Evidence Export" section
3. Click "Export Trust Snapshot"
4. Two files will download automatically:
   - `firsttry_trust_snapshot_<ID>.json` — canonical JSON data
   - `firsttry_trust_snapshot_<ID>.pdf` — formatted report

### Attaching to Questionnaires

**For security questionnaires:**

1. Generate a snapshot using the export button above
2. Attach the PDF to your questionnaire response when asked about:
   - Monitoring and observability
   - Change tracking systems
   - Operational status visibility
   - Data quality and completeness

**For JSON integration:**

1. Use the `.json` file for programmatic validation
2. Verify the SHA256 hash in the JSON matches a recorded value
3. All exported snapshots are immutable and append-only

### Retention Policy

The system retains the last 20 exported snapshots per tenant. Older snapshots are automatically removed when the threshold is exceeded.

## Technical Implementation

### Immutability Guarantee

Each snapshot is:

1. **Canonicalized** — JSON keys sorted lexicographically
2. **Hashed** — SHA256 of canonical JSON computed
3. **ID-based** — Deterministic snapshot ID derived from timestamp + hash
4. **Append-only** — Records never overwritten after creation
5. **Storage-backed** — Persisted to immutable storage

### Data Sources

The snapshot aggregates data only from Phase 1-4 stored observations:

- **Phase 1** — Operational health metrics
- **Phase 2** — Configuration visibility snapshots
- **Phase 3** — Performance and reliability signals
- **Phase 4** — Change awareness timeline (last 30 days)

No new Jira API calls are made during export generation.

### Completeness Status

- **COMPLETE** — All four phase snapshots are present and have data
- **PARTIAL** — One or more phase snapshots present but not all
- **EMPTY** — No phase snapshots available

Missing phase data is recorded in the `issues` section of the snapshot with error code `MISSING_PHASE_SNAPSHOT`.

### PDF Generation

The PDF is auto-generated from the snapshot data and includes:

- Title and evidence identity
- All snapshot sections formatted for human readability
- Footer: "Generated by FirstTry — Read-only evidence export"
- Size limit: max 900 KB (hard constraint)

## Supported Environments

- **Production** — Main deployment environment
- **Staging** — Pre-production staging environment
- **Development** — Local development environment

The environment is automatically detected and included in the snapshot.

## Troubleshooting

**"Export unavailable" message:**

- Ensure the dashboard gadget is fully loaded
- Verify you have access to view the gadget
- Check browser console for any network errors

**Missing phase data in snapshot:**

- Phases 1-4 require initial data collection
- Run the scheduler once (first daily cycle)
- Re-generate the snapshot after first run

**JSON file empty or malformed:**

- Try generating a new snapshot
- Use the PDF instead if JSON issues persist

## Security Notes

- Snapshots contain no sensitive credentials or Jira content
- Data is derived only from stored phase observations
- Export generation does not modify any configurations
- All exports are read-only evidence records
- Snapshots are deterministic (same input → same output)
