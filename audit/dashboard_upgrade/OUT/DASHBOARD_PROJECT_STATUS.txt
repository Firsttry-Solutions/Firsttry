## KEY DECISIONS & RATIONALE

1. **Unified Status Model as Derived Type**
   - NOT stored in database (computed on-demand)
   - Rationale: Reduces storage overhead, always current, backward compatible

2. **Three Component Pattern**
   - KpiTiles: Metrics focus (what's broken)
   - StatusBanner: Overall status focus (is it healthy)
   - ProgressTracker: Process focus (where are we in Phase 4/5)
   - Rationale: Each tells a different story; dashboard can use 1-3 as needed

3. **Icon + Label Accessibility**
   - Even for quick visual scanning, text label always present
   - Icons (✓ ⚠ ✗ ◉) paired with color and aria-label
   - Rationale: Ensures color-blind users and screen reader users have parity

4. **Vertical Timeline over Phase Table**
   - ProgressTracker replaces old table-based phase display
   - Connected steps show progression more intuitively
   - Rationale: Visual storytelling + accessibility + mobile-friendly
